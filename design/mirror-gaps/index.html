    What agentkit f8d20c1 lacks for Mirror¶

    A verified gap list. It covers what Mirror's model-call stack does today, which agentkit at f8d20c1 does not yet do, and what to build so that every Mirror model call (Claude Code CLI, Codex CLI, Anthropic API, OpenAI API) can go through CallRuntime. It was checked against both codebases on 2026-10-13.

    The companion to model-neutral-agents.md, the design. This file is the distance between that design and this commit, measured against a real consumer.

    Path prefixes: - A: is agentkit/ in this repository. - M: is /Users/dododuck/Desktop/work/mirror/.

    Original status: X absent, P partial at the inspected revision f8d20c1. The working-tree implementation status is recorded after the original gap descriptions below; those labels do not change the source snapshot this gap analysis documents.

    The short version¶

    • Gaps that hold back the build and drive lanes but not preflight: native tools and per-call workspace (G14), tool arguments in events (G16), and long sessions (G18).

    G26. A Claude call without tools failed against the real CLI (fixed)¶

    The no-tools default at models/providers/cli/calls.py:391 sends --mcp-config {}. Claude Code 2.1.296 rejects that: Error: Invalid MCP configuration: mcpServers: Invalid input: expected record, received undefined. It does so inline and as a file. {"mcpServers":{}} is accepted. This was checked against the real CLI with an invalid key, so nothing was spent. The no-tools default now uses the valid empty record, and FakeClaudeCli validates inline and file-backed config before consuming a scripted process result.

    Prove: - the fake refuses {} and accepts {"mcpServers":{}}; - a no-tools call succeeds through the fake; - one opt-in real-CLI check with an invalid key reaches authentication rather than failing config parsing.

    G27. A budgeted CLI call does not retry a 429 that reported no cost (fixed)¶

    R4 made each attempt get cap − spent. But a real CLI 429 carries no usage and no total_cost_usd, so spend is unknown, the guard at calls.py:639-648 fires, and the call ends limit_reached without retrying. This was reproduced with FakeClaudeCli: a 429 without usage under max_cost_usd=1 ends limit_reached.

    Prove: a usage-less 429 under a cost cap is retried and answered. Its twin is an attempt with output but no cost, which still stops.

    G28. Non-string secrets reached events (fixed)¶

    R3 masks string leaves only. A numeric or boolean secret, or one used as a dict key, reaches tool_call.arguments.

    Prove: a numeric secret and a secret dict key never appear in a recorded event.

    G29. A host could not set TLS or proxy settings per adapter (fixed)¶

    R2's allowlist (PATH, LANG, LC_*, TERM, NO_COLOR, TMP*) means SSL_CERT_FILE, NODE_EXTRA_CA_CERTS and proxy variables can arrive only ambiently, never through CliAdapter(env=). A deployment behind a corporate proxy or a private CA needs them per adapter.

    CliTransportVariable provides a second named allowlist for TLS and proxy settings through transport=; those same names remain rejected through env=. Base URL and AWS credential variables are not transport settings and are rejected there too.

    Prove: a transport setting passes through transport=; the same name passed as env= is refused; a *_BASE_URL is refused on every path.

    G30. Proof for credential handling end to end (open live verification)¶

    Build: - one opt-in live check per CLI with a real login home. Claude: .credentials.json in CLAUDE_CONFIG_DIR. Codex: ChatGPT auth.json; - one with a refresh forced mid-call, asserting on_changed receives the new file.

    On macOS, confirm whether Claude reads the file or the keychain, and fail closed if it reads the keychain.

    Prove: both live checks pass and are recorded in tests/evals/reports/.

    G31. The argv bound could exceed the per-argument kernel limit (fixed)¶

    max(4096, SC_ARG_MAX // 32) (models/providers/cli/_common.py:939-951) has no ceiling. On Linux with a large or unlimited stack it passes the 128 KiB per-argument limit (MAX_ARG_STRLEN), and an inline payload fails with E2BIG.

    Prove: a payload just over the effective bound goes by file; just under goes inline; and the bound never exceeds the per-argument limit whatever SC_ARG_MAX reports.

    G32. The JSON extractor accepted the last object (reverted)¶

    models/contracts/schema.py:100-106 used to refuse a reply holding more than one JSON object. It now takes the last. A reply that gives the answer and then an example object is read as the example.

    The extractor again rejects more than one complete top-level object as ambiguous. A single stray closing brace remains tolerated. The regression test covers both behaviors.

    G33. UnpricedPolicy.REFUSE stopped refusing (reverted)¶

    At core/runtime/calls.py:718-731, an unpriced token kind under REFUSE now degrades and answers with unknown cost whenever no cost cap is set. That makes REFUSE mean "proceed unpriced" in the common case.

    REFUSE again fails the call when reported token categories cannot be priced. PROCEED_UNPRICED remains the explicit opt-in and preserves partial cost as mixed where possible.

    G34. Usage completeness was inferred from cost (fixed)¶

    At core/runtime/calls.py:556, usage marked incomplete now counts as complete if the provider reports a cost. Cost and token counts are separate facts, and a ledger settling tokens needs to know when they are partial.

    Answer.usage_complete is aggregated independently across turns. A reported cost can be present while token usage remains incomplete; a regression covers that combination.

    G35. A retried 429 makes the answer's cost unknown (P)¶

    When a CLI attempt fails without reporting cost (a 429), the runtime sets the call's total_cost to unknown for good. The budget correctly treats that attempt as zero spent (G27). But the final Answer reports cost_usd=None, cost_source=unpriced, even when the attempt that succeeded reported its cost. Reproduced with FakeClaudeCli: a usage-less 429, then success at $0.20, gives an answer with an unknown cost.

    A ledger reading the answer total then records every retried call as unpriced.

    Build: an attempt that failed with no usage, no cost and no output contributes zero to the total, the same rule G27 applies to the budget. The total is unknown only when an attempt that produced output or usage reported no cost.

    Prove: - a usage-less 429, then success at $0.20, gives cost_usd=0.20 with the source reported; - the twin is an attempt with output and no cost, which still leaves the total unknown.

    G43. One runtime: finish the migration to CallRuntime (architecture)¶

    agentkit carries two runtimes side by side.

    The current one is CallRuntime.ask/run, with AgentRunner.run_agent, Minds, compose, SkillSource, ToolSet, McpGateway, EventHub and WorkingContext/SessionHandle.

    The older one is the Invoker, its middleware and RunContext.services, with: - Agent, RequestBuilder and Workflow; - agents/cognition, agents/policies, agents/control and agents/evaluation; - Observation/ObserverPort; - the state modules: compaction, memory, checkpoints, replay, stores, vectors and leases.

    CallRuntime never touches the older runtime, and the two return different result and usage types with no conversion. The project's own docs name run_agent on CallRuntime as "one path for building a harness".

    Why it matters: - Features read as available and are not. Compaction, memory, checkpoints, guardrails and observers exist and are tested, but no current caller reaches them. - Behaviour is duplicated. Retry, limits and pricing exist as middleware and again in CallRuntime; fixing one does not fix the other. - Downstream code breaks. Consumers built on the older path break when it is reorganised.

    Build: one runtime. Each older piece is rebuilt on CallRuntime, or deleted.

    Older piece Becomes
    Invoker, core/policies middleware, RunContext.services deleted; CallRuntime and the event sinks already do retry, limits, pricing, correction and tracing
    Observation, ObserverPort, integrations/observers deleted; EventHub subscribers
    state/compaction a context_policy: Callable[[WorkingContext], WorkingContext] that run/run_agent applies between slices and before resume; deterministic policies built in, summarising ones explicit opt-ins
    state/memory a memory provider run_agent turns into an untrusted context part at compose time
    state/checkpoints, state/replay, state/stores, state/vectors deleted; continuation is SessionHandle + FrozenContext with the core/serialization codecs; replay is the event journal
    state/leases (timed, renewed) deleted; admission is the untimed acquire hook
    agents/workflows.Workflow deleted; multi-step flows are the host's (or rebuilt over run_agent emitting CallEvents, if a real user appears)
    agents/cognition, agents/policies, agents/control, agents/evaluation, Agent, RequestBuilder, skills.Skill.as_agent, tools/adapters.as_tool deleted; Minds, run_agent, DelegationPolicy and the delegate tool cover them; grading is the host's
    integrations/mcp/approvals.ApprovalServer (bound to the old CLI class) rebuilt on the current CLI adapter's --permission-prompt-tool, with the same approval callback shape as McpPolicy.approval
    core/guardrails (check_url, redact, wrap_tool_output) kept as a library tools call, with an optional ToolSet hook

    Order, so nothing breaks midway: 1. Rebuild the four pieces with current users: the compaction hook, the memory provider, approvals on the current CLI adapter, and G37–G42. 2. Delete the rest in one change, with docs and examples updated and no deprecation shims. Consumers still on the older path stay pinned to a pre-deletion revision until they move. 3. Add the claims test below.

    Prove: - An architecture claims test in agentkit: one Answer type and one Usage type in the public surface; nothing imports a deleted module (a planted import of each is caught); every public module is reachable from CallRuntime or AgentRunner, or is a declared library (guardrails, serialization). - context_policy runs between slices, and the same transcript gives the same result. - A memory provider's items reach the composed prompt as an untrusted context part. - An approval prompt from the Claude CLI reaches the host callback on the current adapter.

    Mirror's cognition already uses only the current runtime, so G43 changes no Mirror design. It moves compaction and memory hooks into agentkit, where Mirror plugs in its own policies.

    G44–G53. What Mirror's build service (forge) needs from the current runtime (2026-10-13)¶

    It serves all file, shell and grep work as its own MCP tools, and denies native tools except web. These gaps were measured against 5ebe4c0 plus the uncommitted working tree.

    Prove: per CLI, a fake that refuses to start unless the expected file is in its home at 0600. The twin is the env-only path, which still works. A file outside the allowlist is refused before spawn.

    G2. A refreshed login is never handed back (X)¶

    Mirror today: seals the CLI home after the call and sends it back to the vault (finish, M:packages/kernel/kernel/authority/session_store.py:657-679). A borrower's refreshed token travels back to the group (session_group.py:179).

    agentkit: deletes the credential files at close (A:models/providers/cli/isolation.py:24-27). snapshot() exports transcripts only (:83-101).

If any changed, await on_changed(changed) exactly once. - If the callback raises, the call's answer is kept, a degraded event records the failure, and the call still ends normally. - Deletion happens after the callback, on every exit path, cancellation included.

    Prove: a fake CLI that rewrites its credential file triggers one callback with the new bytes. The twin is an unchanged file, which triggers none. A cancelled call still deletes the files after the callback.

    G9. A long schema goes on argv (X)¶

    The installed Claude Code 2.1.296 help and current CLI reference expose --json-schema <schema> as inline JSON but no file-backed schema option. The adapter therefore does not invent a --json-schema-file flag. For schemas above 32 KiB and up to 256 KiB, it uses the documented --append-system-prompt-file mechanism to provide schema guidance, then the core parser, validator and correction turn enforce the actual contract. This is an explicit degradation from provider-native constrained output, surfaced as a structured_output degradation event. The larger-schema live case validates this path. See Anthropic's CLI reference and structured output guide.

    Mirror today: keeps the schema off argv when it is too long (M:packages/kernel/kernel/authority/schema_fit.py).

    agentkit: --json-schema goes straight onto argv (A:models/providers/cli/claude/driver.py:1423).

    Build: pass the schema through a file in the isolated home when its encoded size crosses the platform's argv room. Measure that from os.sysconf('SC_ARG_MAX'); never hardcode it.
