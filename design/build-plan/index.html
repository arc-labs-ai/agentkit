    agentkit build plan¶

    The ordered list of changes that makes agentkit the single, model-neutral agent runtime Mirror (and anyone else) builds on. It is the plan to work from. mirror-gaps.md is the record of how each item was found and measured; the item ids (G1–G53) are shared between the two.

    Written 2026-10-13, against 5ebe4c0 plus the uncommitted working tree. Re-check each item's status against the code before starting it: some are partly done in the working tree.

    0. Rules for every change¶

    1. One runtime. CallRuntime (ask/run) and AgentRunner.run_agent on top of it are the only way to call a model. Nothing new may be built on the Invoker, its middleware, RunContext.services, Agent, Workflow or the other older modules. They are being deleted (Phase 3).
    2. Same behaviour on all four modes. Claude Code CLI, Codex CLI, Anthropic API and OpenAI API. Every behaviour lives in the runtime core, never in one adapter. An adapter only translates. Every behaviour gets a conformance scenario in tests/source/conformance/, run against each mode's fake, or explicitly marked not applicable to a mode with the reason.
    3. Test first, and prove the test can fail. Write the test, watch it fail for the stated reason, then implement. Every test has a clean twin, and a test that would pass with the code removed is not a test.
    4. Fakes must be as strict as the real thing. A fake CLI that accepts what the real CLI rejects hid G26. Every fake validates its inputs the way its real counterpart does.
    5. No backward-compatibility shims. Delete old paths in the same change that replaces them. Consumers on an older revision stay pinned until they move.
    6. No timers that mean ownership. No leases, heartbeats or renewals. Admission is the untimed acquire hook. A stall bound is the absence of events, never a wall clock on work that is still producing.
    7. Secrets never reach events, logs or snapshots. Masking is on by default, and the host can supply its own masker.
    8. Report results with their scope. "The conformance suite passes" and "the suite passes" are different claims.

    Phase 3: One runtime (G43)¶

    Goal: one result type, one usage type, one path. Every feature that exists is reachable.

    Do it in this order, so nothing breaks midway.

    1. Move the CLI adapter off the older runtime. The current CLI adapter still uses Agent, RunContext and Budget internally (models/providers/cli/calls.py:107,126,242-246,488-491). Replace them with what it actually needs.
    2. Done when: cli/calls.py imports nothing from the older modules, and all CLI conformance passes.
    3. Rebuild the pieces that have users, as hooks on the current path.
    4. Compaction: context_policy: Callable[[WorkingContext], WorkingContext], applied by run/run_agent between slices and before resume. It is per mode (G46): on the CLI it keeps --resume and sends nothing extra, rather than dropping the native session. Deterministic policies are built in; summarising policies are an explicit opt-in.
    5. Memory: a provider run_agent turns into an untrusted context part at compose time.
    6. Approvals: rebuild ApprovalServer on the current CLI adapter's --permission-prompt-tool, with the same callback shape as McpPolicy.approval.
    7. Done when:
      • the same transcript compacts to the same result twice;
      • a Claude fake keeps one resume id across three compacted slices;
      • memory items reach the prompt as an untrusted part;
      • a CLI permission prompt reaches the host callback.
    8. Delete the older runtime in one change:
    9. the Invoker, core/policies middleware and RunContext.services;
    10. Observation/ObserverPort and integrations/observers;
    11. state/checkpoints, replay, stores, vectors and leases;
    12. agents/workflows, agents/cognition, agents/policies, agents/control and agents/evaluation;
    13. Agent, RequestBuilder, skills.Skill.as_agent and tools/adapters.as_tool.

    Keep core/guardrails as a library tools call, with an optional ToolSet hook. Update the docs and examples in the same change. 4. Architecture claims test: - one public Answer type and one Usage type; - a planted import of each deleted module is caught; - every public module is reachable from CallRuntime/AgentRunner, or declared a library.

    Order, and what each phase unlocks for Mirror¶

    Phase Unlocks
    1 Mirror's one-shot calls (cognition.ask) on API keys, with honest money
    2 Mirror's agent loops (cognition.run_agent) for conversation and analysis
    3 one runtime; Mirror's compaction and memory plug in as hooks instead of living in Mirror
    4 Mirror's build service (forge) on agentkit: long, parallel, fenced, cached CLI sessions
    5 running on real subscription logins in production

    Phases 1 and 2 can run in parallel. Phase 3 step 1 must land before step 3. Phase 4 needs Phase 3's compaction hook (for G46 and G47). Phase 5 runs at the end of each phase on whatever it unlocked.
